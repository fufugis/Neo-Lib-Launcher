## Metadata recovery and repair — planned feature

### Goal

When automatic metadata is uncertain or wrong, NEO-LIB must not silently accept a confident-looking wrong match. It should surface a repair flow comparable to the Wizard: explain what it found, let the user approve/reject candidates, then apply title, developer/uploader attribution where supported, description, images and launch details as one reviewable patch.

### Evidence ladder

1. Start with the executable filename, parent folder names, shortcut target and any existing game title.
2. Inspect only local game-adjacent, human-readable hints: `.txt`, `.nfo`, `.url`, `.ini`, and common `readme` / `about` filenames near the executable. Do not scan unrelated personal folders.
3. Extract likely title, release/version, developer/publisher, store/forum URL, and product identifiers when explicitly present.
4. Search multiple sources using several cleaned title variants, then rank candidates using agreement between local evidence, source title, year/version, folder text, and any known launcher ownership.
5. Show the strongest candidates and their evidence. A low-confidence result becomes a guided question, never an automatic replacement.
6. The user can correct the search phrase, open Google/source search, pick a result, or mark the game as local / custom with manual fields.

### Forum and niche-game handling

- Retain and improve the existing Steam, GOG, itch, DLsite, VNDB, Ryuugames, F95Zone, Google, and optional Ask AI picker.
- Add source-aware query variants from folder/readme evidence and executable cleanup (for example stripping `Win64-Shipping`, `x64`, release tags, and generic launcher words).
- If a forum page explicitly identifies an uploader/developer, present that as its source-labelled attribution. Do not invent a company or state that an uploader is the developer.
- Cache selected artwork and metadata locally only after user acceptance.

### Library Health integration

- Metadata failures and low-confidence titles should appear as actionable Library Health items.
- Review opens the affected game and a `Repair metadata` flow with clear Yes / No / Search again choices.
- Library Health must continue to distinguish missing data from incomplete-but-valid local games.

## Platform-dependent work

- Friends remains a safe native handoff unless an official, opt-in platform API supports presence. Do not scrape friends, credentials, or chats.
- Extend launcher adapters intentionally for detection/import/news/updates; do not claim universal friend or update support where platforms do not expose it.
- Build Update Intelligence for launcher-owned downloads and independently discovered games only after each source has a safe, verifiable way to establish installed versus available version.
