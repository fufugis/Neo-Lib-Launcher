# Native IPC boundary

Renderer-to-Electron commands are registered through `registry.cjs`. It rejects
invalid channel names and duplicate registrations before Electron can silently
replace or conflict with a handler. The registry passes each supplied handler
through unchanged; domain modules may deliberately wrap high-risk handlers with
the shared request guards in `contract-guards.cjs`.

## Current checkpoint

- 88 native commands across 29 named domains are inventoried by
  `scripts/verify-ipc-registry.cjs`.
- Every command invoked by `preload.js` resolves to exactly one native handler.
- `gemini:metadata` is the one documented native-only command and should be
  reviewed as later domains are extracted.
- `persistence-ipc.cjs` owns the stable library/settings IPC surface and delegates
  all document behavior to the versioned document store.
- `window-ipc.cjs` owns minimize, maximize/restore and close. It resolves the
  active window for every call rather than retaining a stale window instance.
- `dialog-ipc.cjs` owns executable, directory, image and save-folder pickers,
  including cancellation and the existing renderer image URL shape.
- `shell-ipc.cjs` owns Windows shortcut resolution; `exe-ipc.cjs` owns native
  executable icon extraction. Both retain their existing safe failure results.
- `system-ipc.cjs` delegates the read-only CPU/RAM snapshot to a stateful,
  independently tested system-health service.
- `playtime-ipc.cjs` delegates range deltas to a playtime-history service backed
  by the versioned document store.
- `image-ipc.cjs` delegates sanitized local artwork caching to an image service.
- `app-os-ipc.cjs` and `app-lifecycle-ipc.cjs` together own all nine `app:*`
  commands: safe external/path actions, auto-start, tray mode and Discord state.
  External actions admit public HTTP(S) plus five exact NEO-LIB-owned Windows
  settings routes; arbitrary `ms-settings:` pages, local files and game-protocol
  launches remain rejected.
- `doctor-ipc.cjs` delegates read-only launch-target diagnosis and ranked sibling
  executable suggestions to a dedicated service.
- Launcher scanner registrations remain generated by the launcher service and
  still pass through the same duplicate-safe registry.
- Every remaining native area now has its own explicit `*-ipc.cjs` contract:
  deals, game, Gemini, GOG, launcher, metadata, news, Optimize, releases, saves,
  scanning, Steam, storage, tools, updates and web.
- `main.js` contains zero direct `registerIpc(...)` calls. It supplies the
  current service functions, then the 29 domain modules register all 88 commands.
- Game launch/watch, save inspection/backup/restore/search, Optimize process/junk,
  storage measurement and directory scanning validate renderer payloads before
  invoking their native services.
- Metadata, news, updates, releases, Steam, GOG, Gemini, public-web and managed-tool
  requests now reject wrong types, oversized inputs, unsupported source/tool IDs,
  unsafe update-history schemes and unbounded fan-out arrays before service work.
  The first two batches account for 35 guarded contracts.
- Launcher actions, external/path operations, lifecycle toggles, library/settings
  saves, playtime, image caching, Launch Doctor, shortcut resolution and icon
  extraction complete the request boundary. All 53 payload-bearing native commands
  are guarded; the other 32 commands intentionally take no renderer data.
- Response guards now cover all 14 game launch/watch, save
  inspection/backup/restore/search and Optimize process/junk commands. Valid success
  and failure results pass through unchanged; malformed native results become an
  `INVALID_RESPONSE` failure with safe empty fields where the renderer expects them.
- A second 14-command response batch covers Steam search/details/manifest/playtime,
  GOG search, Gemini metadata/test/assistant, public-web search, deals and managed
  tool metadata/install/verification/GPU setup. Array/null contracts retain their
  established safe fallbacks; result-object contracts return `INVALID_RESPONSE`.
- A third 10-command response batch covers unified metadata candidates/expansion,
  local metadata hints, launcher-wide news, update scans/history and weekly release
  discovery. These Home/Preview feeds now reject incomplete arrays and invalid core
  fields before the renderer can cache or display them.
- A fourth 28-command response batch covers native dialogs/windows, document
  persistence, directory/storage scans, app OS/lifecycle actions, system health,
  playtime, image caching, shortcut/icon extraction and Launch Doctor.
- The final 15-command batch covers launcher actions, local running/installation
  inspection and installed-game scans for all ten supported launchers. Existing
  scanner fixtures, including Epic's distinct `launchExe`/`launchUrl` shape, remain
  byte-for-byte compatible at the result level.

Domain-contract separation is complete. Many provider, launch, save, Optimize and
metadata implementations still live in `main.js`; moving those implementations
into deeper services belongs to the following architecture stages. Automated
request and response validation are complete for all 88 commands. The same response
boundary catches synchronous service throws and rejected promises, returns the
command's established safe fallback, and writes only channel/domain/failure type plus
an error class to local diagnostics. Request arguments, error text and payloads are
not logged. The dedicated diagnostics domain provides a player-controlled safe report
and log-folder handoff. All six save commands now delegate to `electron/saves/save-service.cjs`,
whose temporary-disk test covers backup data/metadata, path confinement, no-overwrite
restore and bounded searching. `storage-scan-service.cjs` separately owns Home's
user-triggered game/mod folder measurement, validation, shared-root filtering and cache.
`optimize/junk-service.cjs` owns bounded junk discovery and scan-token-guarded Recycle
Bin requests. `optimize/process-inspection-service.cjs` owns normalized performance
snapshots, protected-process rules and cooperative non-force close requests. Deeper
provider/launch extraction and
packaged Windows acceptance are not complete, so

`providers/update-history-provider-service.cjs` now owns the user-triggered public

`providers/deals-provider-service.cjs` now owns Epic, Steam, Instant Gaming, GOG,
Fanatical and Ubisoft deal discovery plus the populated-results-only one-hour cache.
Injected fixtures cover filters, mappings, caps, deduplication, timeouts and isolated

`providers/update-scan-coordinator-service.cjs` owns exact-input keys, the short

`providers/update-source-discovery-service.cjs` owns the bounded saved, official,
Steam, Battle.net and public-search source list used by independent update checks.
Fixed-time fixtures cover matching, confidence, URL cleanup/deduplication, the

`providers/installed-version-evidence-service.cjs` owns bounded local version clues
for independent games. Temporary fixtures enforce absolute paths, two nearby roots,

fixed encoded Windows reader whose target remains environment data.

`providers/update-page-version-service.cjs` owns pure version/build extraction,
numeric comparison, the 80-match cap and trusted-source selection. Text fixtures
prove official evidence wins over search-only numbers while retaining the fallback.

`providers/independent-update-assessment-service.cjs` completes the Stage 4 source
boundary. It owns bounded per-game page fetching, the fifteen-minute evidence cache
and available/current/attention/needs-evidence construction. Cached missing versions
stay missing rather than becoming false-current. Installed evidence now also retains
complete alpha, beta and release-candidate suffixes. `verify-provider-boundaries.cjs`
audits the exact seventeen-service inventory, dependency injection, unique feed routes,
removed legacy caches and guarded review-before-apply flow. The offline suite and the
explicit read-only `npm run test:providers:live` smoke pass; packaged Windows refresh
acceptance remains separate because the managed renderer build cannot spawn esbuild.

The launch implementation now delegates to `game/game-launch-service.cjs`; external
path-only detection and low-usage resume cadence delegate to
`game/external-game-watch-service.cjs`. Both have isolated safety/lifecycle tests.

## Verification

Run `npm run test:ipc` for registry, inventory, preload mapping, guarded request and
all response contracts, plus extracted domain behavior. `npm run prebuild:renderer` also runs
storage, launch-safety and launcher regression suites. These tests do not replace
packaged Windows checks.
